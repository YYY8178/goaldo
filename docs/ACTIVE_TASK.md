## 验收标准

- 开源版方向、唯一阶段目标、期限和停止条件被明确记录。
- 不把 `goaldo-private` 或历史本地工作树整体推入公开仓库。
- 任何代码变更至少通过：

```bash
npm ci
npm run build
git diff --check
```

- PR 描述明确说明公开代码与官方托管服务的边界。

## 禁止事项

- 不提交真实 `.env`、密钥、用户数据、数据库或官方托管配置。
- 不把公开仓库提交视为部署授权。
- 不合并 `main`、创建新发布或修改生产系统，除非维护者另行批准。
- 不在产品方向未确定时继续堆功能。
- 不把闭源产品功能、运营策略或部署配置复制进公开版。
